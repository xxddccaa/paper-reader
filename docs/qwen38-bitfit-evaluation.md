# Qwen3.8-27B 的 BitFit 实测

用户指定接口 `http://127.0.0.1:8000/v1/`，模型标识 `Qwen3.8-27B`。服务返回 OpenAI 兼容模型目录，实际工具调用探测通过。本次只测试同一篇 BitFit，不能据此推断所有论文上的稳定性。

原文：arXiv:2106.10199v5，保留 PDF SHA-256 为 `56a52ea59f763e312687f8b0c1c8953a508c471925f17733e6c580be832000ed`。API/worker 测试通过真实上传接口读取该 PDF。原始产物均在源码外的 `paper-reader-runtime/test-runs/`。

## 最新结果：Workflow v2 已成功发布

2026-10-13，`guided-v2.3` 使用同一模型和 PDF、ljg-paper 阅读指导，完成真实 API → worker → Pi 的首次解读及自然语言表达修订。首次 **448.32 秒、280,852 token**；修订 **120.68 秒、43,470 token**。均为 `succeeded`，共 2 个不可变产品版本，11 条结构化结论和 14/14 条匹配原文的引文。表达修订复用了来源、提取和事实复核，原版及事实包保持不变；真实浏览器成功展示成品和结论。

原始结果、阶段用量、浏览器与逐项复核见 [Workflow v2 评估](workflow-v2-evaluation.md)。逐项回查仍发现任务数和参数占比表述不够严谨；本次未请求外部论文研究，也没有执行完整原生 skill，不能将 guided 的成功记作 native 成功。下面保留改造前的真实结果和当时判断。

## 连接配置与实际修复

- OpenAI Chat Completions 协议，内网模型访问仅在隔离测试 runtime 显式启用。
- 服务无需鉴权：应用 SDK 使用非秘密占位值；未向此接口发送环境中的 OpenRouter 密钥。
- 默认模式的一次完整 agent 尝试约 350 秒失败，累计 91,215 token；其中一轮用满 12,000 输出 token，没有完成 `finish_native`，也没有发布结果。记录在 `live-qwen38-ljg-01/evaluation.json`。
- 额外短句诊断中，默认模式的 256 输出 token 全部计作 reasoning，没有正文；设置 `chat_template_kwargs.enable_thinking=false` 后，约 1 秒、19 输出 token 返回正文。诊断摘要保留在同目录 `thinking-diagnostic.json`。
- 因此增加显式连接选项 `thinking_format=qwen-chat-template`，不根据名字或地址猜测。API 探测与 Pi runner 均把关闭思考传到服务。标准接口与 Anthropic 保持原协议。
- 增加数据库迁移与模型设置 UI。模型配置变更参与排队快照检查；旧快照缺字段时按 `default` 解释。响应输出截断时记录用量并明确失败，不执行不完整工具参数。

修复验证：后端完整 102 项、runner 完整 61 项通过；前端类型检查/构建与 3 项相关浏览器检查通过；迁移回填、回退/升级、无 schema 漂移通过。独立只读复核没有确认的重大问题。这些工程检查不代表模型质量通过。

## 全文直接解读对照

`live-qwen38-direct-01/` 保留 `input.json`、`reading.json`、`brief.md`、`full.md`、`report.json` 和 `human-review.md`。这是关闭思考后的单次全文请求，未经过 Pi、skill、平台复核与发布，单独列为对照。

实际约 **74.6 秒**，输入 **11,844**、输出 **3,856**，共 **15,700 token**，reasoning token 为 0。精华版为 1,319 个 Markdown 字符，其中 551 个汉字，包含较多英文标识、数值和引用。

做对了冻结权重、训练 bias 与任务头、base/large 参数比例区别、子集与随机对照以及作者机制假设的基本组织。但人工回查发现：

1. 将 Adapters 测试集 81.1 同时填入验证集，制造了原文没有的比较单元格。
2. 将“较小学习率收敛缓慢”强化成“必须提高 10 倍，否则欠拟合”，不符合原文证据范围。
3. 在 BERT-large 的成果标题下混入 BERT-base 消融结果，没有交代设置切换。
4. 将 SQuAD 曲线概括成通用样本量阈值；将参数变化分析与随机参数性能对照混为一谈。
5. E7、E13 的实际段落在 PDF 第 3 页，却标为第 4 页。原始引文仅有 2/16 能在只归一空白后匹配所标页；其他项混有 PDF 连字/断词差异、错误页码和转述，不能简单称为 14 条捏造。

原始输出未人工改写。该直接阅读样本不满足严谨论文解读验收。

## 完整 Pi + ljg-paper 流程

修复后的任务在 `live-qwen38-ljg-02/`，从原文重新执行，不复用其他模型写的笔记。配置为 160 次工具额度、1800 秒超时，使用内置精华版与完整版模板。

原生笔记实际生成。格式检查发现图示超宽、正文与 paper-map 的锚点不一致，模型通过多轮重写逐步修正。只改两处引号也需要重写完整记录，增加了生成时间与累计输入量。

独立内容复核实际阻断了两类错误：84.2 被写成高于 84.6；将 Adapters 的测试集成绩混入验证集，并使用误导性的测试集比较措辞。复核依据原文给出了正确方向，模型随后开始修改。

最终在 **1800 秒上限处失败**，错误为 `Paper reading exceeded its configured time budget`，没有发布精华版/完整版。已记录输入 1,812,842、输出 58,900，共 **1,871,742 token**；最后被中断的请求可能未返回完整 usage，不能将此数值当作最终计费量。

共执行 5 次原始校验器，最后一次实际通过。修订后的笔记也曾通过内容与可读性复核，真实报告分别保留为 `passed-content-review.json`、`passed-readability-review.json`。随后模型把这些检查结果写入 paper-map，最终文件需要再次复核；任务在该阶段超时，**没有 host 原生封存**。不能把分阶段通过合并成端到端成功。

完整报告为 `evaluation.json`，最终原生状态为 `native-final-status.json`，原生笔记副本为 `native-note.md`。该笔记是模型产物，未人工改写；人工核对短版另存于 `live-qwen38-direct-01/manual-checked-brief.md`，明确区分作者。

## 改造前样本的判断（历史）

模型有基本的论文理解和组织能力，能执行工具，也能在明确指出错误后修正核心数字比较。但直接输出仍会把条件性观察强化成必然经验，生成没有根据的比较表单元格。独立复核确实识别了问题，却付出了很高的流程成本。

改造前的完整流程不适合承诺稳定交付：大量时间花在整份笔记/研究记录重写、记录内容变化后重复复核上。当时提出优先提供受控的局部修改工具、区分事实内容与检查记录变更以减少重复核查，并继续验证条件性经验与表格的依据。这些改造及新的真实结果已记录于上方 Workflow v2 评估；增加 token 或时间上限本身不能证明质量改善。

这是同一篇论文上的开发实测；直接请求与 agent 流程的提示、输出范围、采样配置不同，不能作为严格的模型/skill 排名或稳定性统计。
