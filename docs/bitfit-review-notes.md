# BitFit 验收核对记录

以下是本次验收时对保留原文的人工核对记录，用于判断实际生成内容。来源为 arXiv:2106.10199v5（2022-09-05），PDF 文件和 SHA-256 见 runtime 的 `test-runs/evaluation-sources/manifest.json`。页码按保留 PDF 的物理页计算。

| 核心事实 | 原文位置 | 容易产生的误读 |
|---|---|---|
| 冻结 Transformer encoder 大部分参数，只训练 bias 和任务分类层 | 第 2 页，§3 | 只说“所有可训练参数都是 bias”，遗漏任务头 |
| Adapters 支持论文定义的任务不变性，Diff-Pruning 不支持；BitFit 也满足该条件 | 第 2 页，§2，criteria (iv) | 把 Adapters 与 Diff-Pruning 的属性颠倒，错误解释相对已有工作的增量 |
| BERT-base 的 bias 约为总参数 0.09%，BERT-large 约 0.08%；每任务还需保存分类器 | 第 2–3 页 | 把所有架构统一写成 0.08%，把参数比例当作计算量/时延下降比例 |
| BERT-large 验证集平均：BitFit 84.2，本次 Full-FT 84.1；测试集平均：BitFit 80.9，表中 Full-FT 81.8/81.5 | 第 3 页，表 1 | 混用验证与测试成绩，称 BitFit 全面超过全量微调 |
| 表 1 的部分 Full-FT、Adapters、Diff-Pruning 数字来自此前工作；QNLI 有测试集更新的可比性注释 | 第 3 页，表注与脚注 4 | 当成同一训练预算、同一代码、完全受控的横向实验 |
| BERT-base 的 query bias 与中间 MLP bias 子集约 0.04%，平均 81.1；全部 bias 82.4；单独 query bias 76.6 | 第 4 页，表 3 | 把作者的“接近”改写成无损，忽略只调一个偏置类型的退化 |
| 同样 0.09% 参数预算：均匀随机选择 78.5、随机行/列 79.5，BitFit 82.4 | 第 4 页，表 3 | 从这个条件下的实验推断“随机稀疏微调永远不可行” |
| 小数据 SQuAD 上 BitFit 更优；数据增多时 Full-FT 更优 | 第 4 页，图 2 与 Size of training data | 给出论文未定义的统一样本数阈值，或外推所有任务与生成式大模型 |
| “微调主要暴露预训练已有知识”是受到结果支持的假说 | 第 1 页摘要，第 2 页讨论 | 写成已经证明的机制 |
| Generalization gap 小于全量微调为定性报告，该段没有精确差值 | 第 4 页 | 为追求数字密度捏造具体差距，或把准确的定性转述误判为质量失败 |
| 数据集排除 WNLI，表中 MNLI 有 matched/mismatched 两列 | 第 3 页，Datasets 与表 1 | 不解释“9 项”来自列数与任务划分差异 |

可迁移经验应表达为：在 BERT 类模型、相近任务与中小训练数据条件下，先将 bias-only + 任务头作为一个低存储成本的基线；若继续缩减到 query/intermediate-MLP bias 子集，应实测其约束下的性能损失；数据量增大、架构缺少 bias 或迁移到生成任务时，需要重新验证。跨任务共享冻结参数是该方法的部署优势，论文没有直接给出训练时间按参数比例线性缩短的证据。

这些记录未注入 agent 的生产提示或工具响应，避免把待评价论文的答案硬编码进阅读流程。最终评价应同时打开生成报告与对应原文，检查它是否保留了必要条件，而不仅仅检查是否出现上述数字。

## 实际原生草稿观察

`live-ljg-06` 和 `live-ljg-07` 的独立模型质量复核曾返回通过，但人工回查原生草稿仍发现表述过强：例如把参数量减少写成已经证明“大幅减少计算资源”，或把“支持暴露预训练知识的假说”写成“模型核心能力已形成，微调只需激活”。另有草稿笼统写 BERT 偏置占 0.08%，没有区分 base/large。原文并不支持这些无条件表述。

这些是原生草稿，不是已发布的产品精华版；对应任务未通过全部原生流程。记录这些问题是为了明确：独立模型复核通过本身不能当作人工质量验收通过，后续产品与人工评测仍须检查条件、范围和因果措辞。

`live-ljg-09` 的重试中，内容复核实际阻断了把 Adapters 与 Diff-Pruning 的任务不变性属性颠倒的错误。人工回查 PDF 第 2 页确认原文为 “The Adapter method, but not the Diff-Pruning method, also supports criteria (iv).” 该例说明复核可以识别具体问题，但不能抵消前述漏报，也不构成整体稳定性的统计证据。

该重试的最终原生笔记已通过脚本和两类模型复核，人工仍发现以下残余问题。原始产物保留原样，未替模型修改或重新制造通过记录：

- 结尾写“不到万分之一”，与正文的 0.08% 不符；0.08% 是万分之八，0.09% 是万分之九。任务头还需要单独计入。
- SQuAD 的字符趋势图画成两条随数据量下降的曲线，无法准确支持正文所说的小数据/大数据相对优势切换，容易误导读者。
- 正文直接写 GLUE 的“9 个任务”，没有解释 WNLI 排除及 MNLI matched/mismatched 两列；开头多次泛指 0.08%，没有始终限定 BERT-Large。

这些问题出现在原生笔记中，后续产品生成及复核尚未完成：任务在产品阶段遭遇 HTTP 429，没有发布任何产品版本。它们说明当前质量与成本仍需后续真实评估，不能把原生自动通过当成整个读论文产品已经解决痛点。
