# 私有论文追问交付记录

本次实现沿用现有 Pi 1.1.0、PostgreSQL 与解读版本存储。在论文解读页面增加持续追问：回答读取所绑定版本的原文，保留多轮历史，按需检索相关论文，流式显示草稿，再执行引文匹配与独立内容复核。聊天不会创建或修改正式解读版本。

## 实现范围

- 桌面侧栏和手机抽屉；新话题、历史恢复、停止、重新回答和每轮独立的引用抽屉。
- 私有会话和消息表；幂等发送、顺序分配、历史分页、可重放 SSE。团队管理员与其他成员不能通过应用接口查看他人的对话，通用任务接口也不能绕过这一限制。
- Pi 恢复经过授权的历史，使用真实 `text_delta` 输出；回答、复核和压缩有不同工具权限。只有回答正文进入流式展示，独立复核及压缩内容不展示为回答。
- 后台按实际原文核验引文，并交给独立模型会话检查论断、数字、条件和归属。错误最多触发三轮针对性修复；仍有缺口时保留可用回答与明确说明。
- 原始来源按内容哈希保存，消息只引用来源和元数据，避免每轮复制整篇论文。历史相同的 `E1` 会附带各自轮次、来源、章节和页码定位。
- 长对话同时按模型预算和 400 条历史边界压缩；原始消息仍保留。模型继续读取原文时也检查上下文预算，明确省略过旧工具结果，保留当前问题与提交能力。
- 沿用已有任务租约、取消、重试、恢复和用量统计；更新服务前保留数据库、配置与来源文件备份。

接口、数据与任务分工详见 [paper-chat-contract.md](paper-chat-contract.md)。

## 实际分工与独立审查

按 `parallel-feature-delivery` 技能执行，四个实现 agent 独占文件：`chat_api` 负责数据/API/迁移；`chat_flow` 负责检索/验证/修复/压缩；`chat_runner` 负责 Pi 会话/流式/工具约束；`chat_ui` 负责界面和浏览器测试。主 agent 集成后台任务、私有来源缓存、生成接口类型，并负责部署和真实验收。`review_titles` 执行独立只读审查。

审查发现并修复：中断发布导致缓存不能重用、历史来源重复存储、短消息超过 400 条未压缩、历史引用定位缺失、工作空间 arXiv 别名绕过来源计数、中文与工具续推上下文预算不一致。集成另补充了修复尚未输出新正文时保留上一版草稿的处理。

服务在 2026-10-14 完成数据库迁移至 `4c7b35a912df` 并恢复健康检查。迁移前的数据库、配置和来源文件备份位于 `preview/backups/before-paper-chat-20261014T113923Z/`，权限限制为当前运行用户。

真实首轮检查发现此前模拟整数时间预算未覆盖的兼容问题：剩余秒数带小数，转换得到浮点毫秒，Undici 拒绝该 timeout 参数，而 SDK 将它包装成 `Request timed out`。同一模型的连接测试成功；直接对比浮点与整数 timeout 也复现了差异。该问题在网络层统一取整修复，随后通过原消息重试继续验收；首次失败记录保留于 `live-turn-1-*-initial-failure.*`。

第二问还触发了真实模型的自然结束行为：模型写完正文后返回普通 `stop`，没有调用结构化提交工具。为此补充仅限聊天的同会话自动续接，最多两次提醒模型用现有草稿与原文依据完成提交，沿用原有预算。取消、输出截断和明确的模型服务错误不触发该续接。失败草稿和首轮验收记录均保留，再通过原消息重试验证修复。

## 当前边界

会话固定到开始时选定的解读版本。每轮最多读取三篇外部论文，使用共享的 300 秒与 48 次工具调用预算。网络失败、证据不足和复核未通过会明确说明；引文匹配、内容复核和资料范围分别展示，已有正文仍可查看。首版不提供会话共享或删除接口。只有成功完成的问答对进入后续模型历史，部分完成及失败内容仍保留供用户查看，已取得的外部原文可继续复用。对话摘要只用于保持上下文，引用仍须回查保存的原文。
