# Paper Reader agent runner

Requires Node >=22.19.0. From this directory run `npm ci`, `npm run build`, `npm test`. `dist/index.js` is a one-job JSONL process, launched by the Python worker. Its only stdout is structured protocol events; stdin receives the run specification and correlated worker tool responses. See `../docs/contracts.md` for the public protocol.

The implementation uses `@earendil-works/pi-coding-agent` and `@earendil-works/pi-ai` 1.1.0. Each model context has an in-memory session, credential store, model catalog and settings. No disk-based auth, resource discovery, builtin shell tools, extensions, prompt templates or project instructions are loaded. Only the supplied tenant model and explicit paper tools are enabled.

The `pi-agent-v1` execution engine uses one persistent main Pi session for reading, revision or private chat. The host supplies dynamic tool schemas and a compact task overview; the Agent chooses reading, drafting and repair actions. A complete model proposal is checkpointed before tools execute, and every complete tool result is checkpointed afterward. Runner-generated call UUIDs survive restart, allowing the host to replay cached effects after a crash without duplicate writes. Failed, cancelled or truncated proposals never become replayable effects. Model requests have a 300-second whole-stream limit; recoverable errors return to the same Agent. The host owns accumulated time/tool budgets and trusted publication. Exhaustion or persistent blockage returns `waiting`, preserving work for continuation. See `../docs/pi-agent-v1.md`.

Fresh reviewer and bounded subtask sessions receive only read-only host tools and runner-internal `submit_review` or `submit_subtask`; they share host attempt accounting but cannot overwrite the main checkpoint. The main Agent cannot issue passing host attestations. Reviewers must consume returned evidence/images in a later model request before submitting a verdict. Context bounding preserves current visual pixels or fails explicitly, and idle SDK compaction preserves original artifacts while saving a separate continuity summary. Chat drafts are written by host tools and remain pending verification.

Legacy guided phases and the native compatibility path remain available. Native skill execution, native reviews, product generation and independent product review retain their existing separate stages. Native findings remain in artifacts, user templates shape a separate result, and failed product review gets one targeted repair. The worker validates evidence and is the authority for lease/cancellation/publication. A model-authored `verified` flag is always reset to false before worker verification.

`npm test` uses an explicit local HTTP OpenAI-protocol fixture to exercise the actual SDK, tool dispatch, usage, cancellation and gates. It does not claim reading quality. `OPENROUTER_API_KEY=... node tests/live-sdk.mjs` is a separate opt-in paid network smoke that verifies one actual Qwen tool call; never pass the key on a command line or check it into a file. Full paper reading evaluation is separate from SDK protocol testing.

Skill pins, differences from desktop operation, and limitations are documented in `../skills/ADAPTATIONS.md`. No fixture or demo fallback exists in the production runner.

Native review/seal RPCs are host-only and are never registered as model tools. `host_native_attest` carries the host-read note/map SHA-256 plus results from independent model contexts; `host_native_seal` verifies actual script semantics and file integrity before product writing. A revision calls the seal RPC without paths to validate the prior seal. The model-visible `read_native_contract` RPC projects the fixed bundle's writing contract without loading image metadata into context.

The Pi runtime injects `transport.ts` into actual provider calls. Its undici socket lookup checks all DNS answers and returns those exact addresses, so DNS validation cannot be bypassed by a later independent resolution. Literal private addresses, off-origin/base-path requests and redirects are rejected. `model.allow_private_models` is supplied only by deployment configuration through the worker. No process-global fetch or credential override is installed.

On every attempt, host-only `host_native_status {}` verifies whether a native seal already exists. A restarted original reading with a valid seal reuses the returned note/map/reviews and continues product generation, even though `kind` remains `read`. `native_reused` and `native_reuse_reason: checkpoint_recovery` distinguish this from a new native run or a user revision. Missing seals run the native workflow normally; invalid seals fail closed.
